# Dev Library 配置

Dev Library 0.2 将三个作用域作为彼此独立的资料库加载，并把有效条目合并显示；同名或同 ID 条目不会互相覆盖。

| 作用域 | 位置 | 用途 |
|---|---|---|
| 全局 | IDEA 配置目录下的 `dev-workspace/library` | 所有项目可见 |
| 项目共享 | `${PROJECT_DIR}/.dev-workspace/library` | 可随项目版本控制共享 |
| 项目私有 | IDEA system 目录下按项目路径散列的目录 | 仅本机项目可见 |

每个作用域包含 `library.json` 和可选的 `contents/<item-id>.md`。`library.json` 保存分组、标签、说明和目标路径等元数据；外部文件、图片和媒体始终只是路径引用，插件不会复制或删除它们。

## JSON 版本与迁移

版本 1 的 `library.json` 和旧 ZIP 归档继续可读。版本 1 条目加载时
`source` 视为 `null`；任何后续保存和新导出都统一写为 JSON 版本 2。
迁移不会改变已有条目 ID 或 `contents/<item-id>.md` 文件名，未知版本仍会被拒绝。

版本 2 可为条目保存结构化来源：

```json
{
  "source": {
    "kind": "EDITOR_SELECTION",
    "path": "${PROJECT_DIR}/src/Main.kt",
    "startLine": 4,
    "endLine": 8
  }
}
```

来源行号从 1 开始。`startLine` 与 `endLine` 必须同时存在或同时省略；
来源只描述原始位置，不替代条目的 `target`。

项目内路径以 `${PROJECT_DIR}/relative/path` 保存并使用正斜杠。项目外路径保存为规范化绝对路径。移动或删除资料条目只更改资料库元数据；“重新定位”也不会移动外部文件。

Markdown 正文由插件写入当前作用域的 `contents` 目录。外部修改 `library.json` 或 Markdown 正文后，资料库会重新加载；单个损坏作用域保留自己的最后有效快照，不影响另外两个作用域。

导出 ZIP 仅包含清单、资料库 JSON 和插件拥有的 Markdown 正文，不包含外部目标文件。导入会先完整验证和暂存，再提交到明确选择的目标作用域；冲突 ID 会重新生成，同名分组会复用。

“打开资料库”和“快速添加到资料库”均可在“设置 | 键位映射”中配置。0.2 不预设快捷键，也不包含 WebDAV、GitHub、自定义服务器或其他远程同步。

## 详情与来源跳转

详情区显示完整元数据、目标、结构化来源、状态和时间，并继续提供
Markdown/图片预览。URL、目标路径和来源位置可点击和复制：

- URL 使用系统浏览器打开；
- 文件目标每次点击都重新检查状态，并使用资料库的智能打开策略；
- 来源文件每次点击都重新检查存在性，再在 IDEA 编辑器中打开；
- 来源起始行超出 EOF 时定位到最后一行并提示；
- 来源结束行超出 EOF 时将选区截断到最后一行；
- 缺失文件、无效路径或无项目上下文只显示本地化警告，不抛出未处理异常。
